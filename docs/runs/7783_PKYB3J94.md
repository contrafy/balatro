What made the build work: a "Full House engine" assembled by ante 3-4 and never changed:
  - Jolly Joker (+8 mult if hand has a Pair) and Sly Joker (+50 chips if hand has a Pair) both trigger off the
    PAIR embedded inside a Full House (trips+pair), not just standalone Pair hands - this was the single biggest
    lesson of the run and was not obvious from the playbook.
  - Supernova (+mult = times this hand type has been played) rewarded replaying the same hand type (Pair AND
    Full House both accumulated their own counts) every single hand.
  - Cavendish (x3 xMult) and Hologram (xMult growing +0.25 per card added to the deck, reached x2 by ante 6) were
    kept rightmost via `order` so the flat +mult/+chips jokers applied before the multiplicative ones.
  - Aggressive hand leveling: Full House reached L6 (165x14) via two Earth tarots plus a Black Hole spectral card
    (which leveled ALL hand types by 1 in one shot - the single best purchase of the run, found in a Jumbo
    Celestial Pack at ante 5). Pair was independently leveled to L5 as a deliberate fallback hand for boss blinds
    that penalize Full House specifically (The Arm: -1 level to the played hand; The Club: a suit debuffed).
  - Play pattern: every blind, discard aggressively (using all 2-3 discards) hunting for a triple + pair
    (Full House), keeping any made pairs and cutting singles. This consistently produced a Full House within
    3 hands. When a boss blind punished playing Full House directly (The Arm), a plain Pair was played instead to
    protect the Full House level, at real but acceptable cost (much lower score that hand, still enough to clear).
  - Calibration note for the CLI's `hands` estimator: for a Pair, `est` matched the actual score almost exactly.
    For a Full House, actual score was consistently 2x-4x the printed `est` (e.g. 7080 est -> 26550 actual, 10202
    est -> 38955 actual) - the estimator appears not to fully account for the compounding of Cavendish/Hologram
    xMult with Jolly+Sly+Supernova all firing together on the hand's internal pair. Treat Full House `est` as a
    floor, not a ceiling, when deciding whether to keep discarding for a bigger hand.

Bridge issues / CLI problems encountered this run (exact behavior):
  1. `buy J2` (using the shop's printed label like "J2") did not buy the item labeled J2 - it bought slot 1
     instead (the game's own internal shop-slot numbering, not the printed label). Always re-check `s` or the
     `legal` output's `{"slot": N}` field before buying, don't trust the printed "J1:.../J2:..." labels as the
     literal argument to `buy`.
  2. After a pack's first `pick`, the CLI sometimes still prints "Pack (choose N)" with leftover cards even
     though the pack only allowed 1 selection (observed with a regular Celestial Pack and a Jumbo Standard Pack,
     both single-pick packs). A second `pick` call then returns `ACTION FAILED: Invalid pack card index None`
     with no cost/side effect - harmless, but the "choose N" line cannot be trusted as the true remaining-pick
     count; run `s` to confirm the pack actually closed.
  3. Opening a Buffoon/Arcana pack while all 6 joker slots are full sometimes leaves only `SKIP_PACK` as a legal
     action (no `SELECT_PACK_CARD`) even though the pack listing shows joker options - the $4-6 cost is still
     charged with nothing gained. Sell a joker (or check joker-slot count) before buying a joker-type pack.
  4. `cash` immediately after a very large scoring hand (e.g. 10089, 31883, 38955) frequently returned
     `ACTION FAILED: Round eval blocking events still pending, retry shortly` on the first attempt; a single
     `sleep 2` + retry always succeeded on the second try. This appears correlated with bigger scores (more
     on-screen scoring animation/events to resolve), not a bug per se, but worth expecting on any high-scoring run.
  5. Fatal for this run: the shared multi-instance harness (`instances.sh`) can be stopped/restarted by another
     concurrent agent session with no isolation between ports - a bulk restart triggered elsewhere killed this
     run's dedicated port (7783) mid-run with no warning and no way to recover from inside this session. This is
     an infrastructure-level problem, not something an agent following the playbook can defend against.
