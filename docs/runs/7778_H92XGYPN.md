Post-mortem:
  Binding constraint: scaling, not misplay. Main hand (Pair) was only L5 with two flat-mult jokers (Jolly, Clever)
  and zero xMult jokers all game; The Wall's x2 chip requirement (20000 vs the normal 10000) is exactly the "boss one
  ante later" case flagged in playbook 7a, and our engine (leveled Pair/straights of opportunity, no leveled Full
  House play, no xMult) could not double fast enough. We entered ante 4 boss with 0 xMult sources despite two Justice
  tarots successfully converting cards to Glass (x2) -- those conversions helped (+618, +confirmed working) but
  affect only the specific enhanced card, not the whole hand, so their contribution was marginal next to a real
  xMult joker.
  Decision I would change: at the ante-4 shop (5/6 then 6/6 jokers), I filled the last slot with Fibonacci
  (conditional, rank-gated +mult) instead of continuing to reroll/save for any xMult joker (Hologram, Photograph,
  Card Sharp, The Duo, etc.) even though none had appeared in ~6 shop visits this run (matches playbook 7a's
  "xMult offered in 1 of 46 visits" data point). With hindsight, given The Wall was the very next boss, spending the
  ante-4 gold on hand levels (we still only reached Pair L5 / Full House L3) or holding for a reroll hunt for xMult
  would have been better than locking the last joker slot with a situational Fibonacci that only fires on
  Ace/2/3/5/8 pairs.
  Money was never a constraint (spent everything every shop per playbook, correctly never idle) -- the constraint
  was pure damage output at ante 4 against a doubled boss requirement.
  est vs actual: every single play this run tracked estimate exactly (0% deviation) except the very first Justice-
  enhanced Two Pair (est 5562, act 6180, +11%, because `advise`'s est is computed before the Glass-card enhancement
  is applied that same turn -- worth noting for future runs: apply card enhancements with `sel`/`use` BEFORE running
  `advise`/`hands` if you want the estimate to reflect them).
Bridge issues: `play STRAIGHTFLUSH i j k l m` on an Ace-high 5-card straight flush was ABORTED with
  "these cards form Royal Flush. Re-run hands and pick indices again." -- the game distinguishes ROYAL FLUSH from
  STRAIGHT FLUSH as a separate type name even though `hands`/`advise` list it under "STRAIGHT FLUSH". Had to retype
  the command as `play ROYALFLUSH i j k l m`, which worked. This cost one wasted CLI call (no game-state cost, just
  time) -- worth adding ROYALFLUSH as a documented type word alongside STRAIGHTFLUSH in playbook section 7a.
Playbook suggestions:
  1. Document `ROYALFLUSH` as a distinct required type word (A-K-Q-J-T of one suit): `play STRAIGHTFLUSH` on it
     aborts even though `hands`/`advise` label the candidate "STRAIGHT FLUSH".
  2. Note that `advise`/`hands` estimates do not include a card enhancement (Glass/Steel/etc.) applied earlier in
     the SAME action sequence unless `sel`/`use` was run before the `advise`/`hands` call -- apply enhancements
     first, then re-run `advise` for an accurate number.
  3. Reinforce 7a's data point in the shop procedure itself: with 0 xMult after ~6 shop visits by ante 4, prefer
     rerolling or saving over spending the LAST joker slot on a conditional flat-mult joker (Fibonacci/Even
     Steven/etc.) when a boss blind with a doubled requirement (The Wall) is next -- a free slot kept for a
     same-shop xMult reroll may have been worth more than Fibonacci here.
